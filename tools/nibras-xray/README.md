# Nibras X-Ray — Source Code Analysis & Architectural Intelligence Platform
**Brand:** Nibras Code | **Product:** Nibras X-Ray v1.0

Nibras X-Ray is a full-stack static analysis, dependency graph, vulnerability detection, and architectural visualization platform for JavaScript, TypeScript, and Python codebases.

## Architecture & Module Overview
1. **Project Scanner (`backend/app/services/zip_scanner.py`)**: In-memory safe ZIP extraction with strict defenses against path traversal (`../`), symlink escapes, and ZIP bombs (compression ratio, entry count, and uncompressed byte caps).
2. **Real AST & Lexical Parsers (`python_analyzer.py`, `jsts_analyzer.py`)**:
   - Python: Uses Python's native `ast` module for exact syntax error detection, function/method/class extraction, cyclomatic complexity calculation, variable scope/mutation tracking, unused import detection, and security sink inspection.
   - JavaScript/TypeScript: real `@babel/parser` AST via the Node worker `backend/app/services/babel_ast_worker.js` (functions, arrow functions, classes, methods, typed params/return types, imports + unused imports, `const` reassignment, loose equality, eval / innerHTML / hardcoded secret / SQL-template sinks). Requires Node.js and `npm install` in `backend/`; `/api/v1/health` reports `unavailable` otherwise.
3. **Graph & Hotspot Engine (`graph_engine.py`)**:
   - Builds module dependency graphs and function caller/callee graphs.
   - Runs Tarjan/DFS cycle detection to highlight circular imports.
   - Calculates transparent, documented Hotspot Scores and Oman & Hagemeister Maintainability Index (0–100).
   - **Impact Simulator**: Computes direct and transitive blast radius across functions and files.
4. **Provider-Independent AI Code Explainer (`ai_explainer.py`)**:
   - Keeps API keys strictly server-side and requires explicit user consent before sending private code externally.
   - Includes a deterministic, AST-grounded explanation engine that synthesizes exact signatures, callers, callees, variables, and remediation steps without hallucinating symbols.

## Running Locally

### 1. Backend (FastAPI, optional)
```bash
cd backend
npm install            # installs @babel/parser for the JS/TS worker (Node.js required)
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 2. Run Automated Test Suite
```bash
cd backend
PYTHONPATH=. python3 -m unittest tests/test_nibras_engine.py -v
```

### 3. Interactive Self-Contained Workbench
Open `nibras_xray.html` in a modern browser (or use https://nibrascode.com/xray) for the 4-pane workbench with in-browser ZIP extraction (`JSZip`) and static analysis.

## What works where (honest status)

| Feature | Browser (nibrascode.com/xray, no server) | FastAPI backend (optional, self-hosted) |
|---|---|---|
| ZIP / folder upload, file tree, graph, 3D view, reports | ✅ on-device, nothing uploaded | ✅ |
| JS/TS syntax errors | ✅ `@babel/parser` (ESM build loaded from esm.sh) | ✅ `@babel/parser` Node worker |
| JS/TS symbols, calls, security rules | ⚠️ heuristic/lexical in the page | ✅ AST-based worker |
| Python | ⚠️ heuristic (no Python `ast` in the browser) | ✅ Python `ast` |
| Go/Rust/Java/Kotlin/PHP/C++/Dart | ⚠️ heuristic | ⚠️ heuristic |
| GitHub import | ✅ public repos via GitHub API (rate-limited) | – |
| SARIF / DNA / taint-flow / executive report APIs | – | ✅ |
| AI explanations with external LLM | ❌ | needs server-side API key + user consent |

The website deploys **only the static workbench** (`public/xray`, generated by `node scripts/build-xray-pages.mjs`). The FastAPI backend is **not** deployed to Vercel (Hobby: 12-function limit, no Python server); it stays here for self-hosting/Docker.

`docs/frontend-stub-unused/` is the unfinished React/Vite frontend (only an API client + package.json). It is **not** the product and is not built; the shipped UI is `nibras_xray.html`.
